# 法律风险与运营约束

检索日期：2026-09-18（北京时间）。以下是本项目的产品和运营风险约束，不能代替针对真实运营主体的中国法律意见。

## 核心原则

开源、免费、数据与代码分离、GitHub 境外托管、签名验真和“仅供参考”声明，都不能使虚假事实、名誉侵权、个人信息泄露或其他违法行为免责。技术校验解决来源和完整性，不解决事实真伪及发布是否合法。

本版先完成工具能力，不建立真实企业初始表格。所有真实名单上线前均须按本文规则逐条审查。

## 已落实到基础版的控制

1. 采用作息事实索引，不使用“黑榜”“良心认证”“违法企业”“抵制榜”等直接评价。
2. 每条资料限定经营主体、地点、岗位、用工方式和时间，区分招聘口径与实际执行，不外推整个品牌和供应链。
3. 正式数据需要公开来源；无法核实的消息不能伪装为已核实事实。赞踩数、AI 判断、未找到投诉均不等于证明。
4. 投稿要填写办公室或工厂等地点类型，允许“待补充”，不强制把事实压成好 / 差二选一。
5. 提交前提示公开性，禁止个人身份材料、工牌和内部文件；初步检测手机号、身份证号、邮箱和部分侮辱性词语。这种检测存在误报与漏报，不是法律审核或匿名化认证。
6. 提供资料更正与企业异议入口。未经审核的 Issue 不进入客户端目录。
7. 仅提供主流购物平台链接和公开门店位置；演示链接标注平台搜索，不伪称官方旗舰店。总部制度不代表具体商品的代工厂。
8. 购物不在 App 内成交；不收佣金、排名费用或删评费用。将来增加广告、返利或商业合作，必须重新审查产品定位及相应义务。
9. 不抓取或重新分发整篇报道、裁判文书、商标、商品宣传图或员工照片；生产资料只保留必要事实摘要与合法来源。
10. 不提供 VPN 服务或绕过网络限制教程。网络失败通过文件导入处理。

## 正式公开运营前必须具体化

| 事项 | 需要落实的结果 |
| --- | --- |
| 运营主体与联系方式 | 明确负责审核、投诉、隐私和安全事件的人或组织，提供真实可用的投诉入口 |
| 网站 / App 上线形式 | 按实际部署、服务对象、经营方式、分发渠道确认备案、许可及平台规则，不能预设境外托管一律豁免 |
| 投稿隐私与出境 | 评估 GitHub 账户、投稿内容及运营者的处理角色和跨境流程；依法确定告知、处理基础、单独同意、评估或其他适用要求及豁免 |
| 企业商誉与资料审核 | 建立来源核查记录、主体消歧、同名公司核对、争议处理和必要复核，不制造未经证实的全品牌结论 |
| 数据与代码许可 | 选择代码许可证；另行确定数据许可，并排除无权再许可的第三方内容 |
| 申诉受理 | 公开资料异议可走 Issue；需要真实身份或私人证据的程序必须走合规私密渠道，不要求在公开 Issue 上传证件 |
| 离线传播 | 告知更正和撤回不能控制所有离线副本；新包携带更正并增加版本，重要更正同时发布公告 |
| 密钥与软件发布 | 配置正式密钥、权限保护、备份与泄露处置；未经审核不能自动签发 |

运营建议：对疑似隐私泄露、明显失实或紧急侵权通知及时分流，采取必要措施。普通异议可设置例如 2 个工作日内确认收到、7 个工作日内给出处理状态的内部目标；这些是建议服务目标，不是法定免责期限，具体流程与保留期限应经律师确认。

对疑似失实信息不能仅增加“有争议”标签后继续放任传播，也不能把“对方没有回复”当成事实成立。投诉人、被投诉人和投稿者的个人身份材料不得随公开更正记录披露。
